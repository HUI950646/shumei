雷达和摄像头连接说明
项目：基于多模态数据融合的目标检测系统
整理日期：2026-10-20

1. 目前约定的接线

摄像头 → 网线 → USB 转网口 → 电脑 USB
雷达   → 网线 → 电脑自带 RJ45 网口

这里“USB 接摄像头”指 USB 转以太网适配器，不是电脑内置摄像头或 USB 摄像头模式。
两台设备均需按自身要求供电。普通电脑网口、USB 转网口不等于 PoE 供电口。
摄像头已单独供电时可按上面直连；若使用 PoE，则电脑接注入器 LAN 数据口，
摄像头接匹配的 PoE 输出口。
需要两块能被 Windows 正常识别的有线网卡；也可以用两块 USB 转网口。
Wi-Fi 可继续上网。设备直连网口显示“无法访问 Internet”不影响设备通信。

2. 已验证的地址（是这两台设备当前配置，并非所有同型号的出厂默认值）

雷达：TCR300，TCP 192.168.10.123:50000
电脑接雷达的网卡：192.168.10.50
子网掩码：255.255.255.0；网关、DNS 留空

摄像头：192.168.1.11
摄像头网页：http://192.168.1.11/
摄像头取流：rtsp://192.168.1.11/（端口 554）
电脑接摄像头的网卡：192.168.1.50
子网掩码：255.255.255.0；网关、DNS 留空
摄像头 ONVIF 硬件标识：T5AI-W/IPG-5950PCS-AI
已读取的视频：H.265，800×448

不要把电脑地址设成设备自身的 192.168.10.123 或 192.168.1.11，以免冲突。
新电脑网卡名称不一定叫“以太网 2”，按实际线缆对应关系手动配置即可。
这些操作由接手电脑自行完成；包内不自动修改系统网卡、驱动或防火墙。

3. 项目里在哪里改地址

config/devices.json：
  radar.host          雷达 IP
  radar.port          雷达 TCP 端口
  radar.localAddress  电脑接雷达的网卡地址（后端会显式绑定）
  camera.rtspUrl      摄像头 RTSP 地址
  camera.localAddress 电脑接摄像头的网卡地址
  camera.pythonPath   新电脑用于视频采集与推理的 python.exe 完整路径
                      留空时使用项目内 .venv/Scripts/python.exe
  camera.modelPath    默认 models/yolov8n.pt，相对于项目根目录
  camera.fps          期望输出帧率，默认 10
  camera.enabled     false 表示暂时只运行雷达

如果设备 IP、端口或认证信息改变，按实际值更新此文件，并重启后端。
Windows 路径建议写正斜线，例如 D:/envs/sentinel/python.exe。
启动入口是项目根目录 launch.mjs，不依赖旧电脑的 Anaconda 路径或网卡 MAC。

4. 数据链路

雷达 TCP → sentinel-backend/src/live/tcr300.ts 解码
         → src/live/service.ts 组帧 → WebSocket → 前端雷达/指标面板

摄像头 RTSP → scripts/live-camera.py（OpenCV 解码 + 本地 YOLO 推理）
            → src/live/camera.ts → 同一序列的 JPEG 和检测框 → 前端摄像头视图

网页：http://127.0.0.1:4173/
后端：http://127.0.0.1:3001/
数据流：ws://127.0.0.1:3001/stream
状态：http://127.0.0.1:3001/api/live/status
当前帧：http://127.0.0.1:3001/api/live/frame
图像：http://127.0.0.1:3001/api/live/camera/{sequence}.jpg

上方“雷达探测 / 摄像头感知 / 风险场”切换视图。
判断雷达在线：radar.state=streaming，cycles 持续增长。
判断摄像头在线：camera.state=streaming，sequence 持续增长。
目标数为 0 可能只是没有探测到目标，不能只凭目标数判断设备是否断开。

5. 已验证与尚未完成的部分

摄像头已经接通，真实道路画面、车辆/行人检测框、类别与置信度均已验证。
TCR300 曾经接 USB 转网口，实际收到了目标；解码与 483 条历史厂家回调逐条核对。
之后按用户要求交换接线，雷达改接原电脑自带 RJ45，但该网卡未被 Windows 识别，
因此打包时雷达暂时离线。换电脑后需重新确认两块有线网卡均正常识别。

实时雷达与摄像头还没有完成本次现场的联合标定、时间同步和可靠身份关联。
视觉 ID 不是雷达 ID；未关联的视觉目标速度、方位角和实时风险保持未知。
本机已接入基于实时雷达位置与速度的相对风险估计，页面标明“雷达估计”。
该场使用距离、径向接近速度与近似 TTC 计算归一化研究指数，并沿运动方向扩展；
它不代表事故概率，也不代表已完成雷达与摄像头融合。
联合风险场仍需现场标定与同步，不能直接套用旧录像的风险矩阵。
历史回放已有原始风险矩阵与等高线，这是保存的数据，不代表实时融合已经完成。
传感器 +Y 尚未完成正北标定；摄像头画面内时钟也尚未校准，当前使用电脑接收时间。

6. 常见问题

雷达显示网卡未就绪 / EADDRNOTAVAIL：
  先确认电脑有 radar.localAddress 对应 IP，且系统已识别该物理网卡。
网口灯亮但找不到网卡：
  检查电脑/网卡驱动与设备管理器；灯亮不代表 Windows 已识别网卡。
TCP 超时：
  检查供电、线缆、网段和设备端口；避免其他上位机同时占用雷达连接。
摄像头有网页但无视频：
  核对 RTSP 地址、Python 环境、OpenCV/PyTorch/Ultralytics 依赖。
刚开始视频灰屏或解码等待：
  H.265 连接后需等待关键帧数秒，后端会丢弃过期帧并重连。
页面显示“风险未知”：
  未关联视觉目标、雷达数据过期或断线时保持未知，不是风险值为零。
  雷达在线且没有目标时显示空场和明确提示；有目标时显示雷达估计热图。

新电脑环境安装和系统配置由接手者自行处理。项目文件说明见包内 README.txt。
